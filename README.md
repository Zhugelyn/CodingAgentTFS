# ArioCodingAgent

Харнесс из трёх агентов (analyst → developer → reviewer) на OpenHands SDK. Берёт тикет, находит место проблемы в коде Directum RX, вносит правку, собирает решение и проверяет её. Результат остаётся в репозитории RX на отдельной ветке тикета **без коммита и push**: их делает человек.

Оркестратор (`src/ario/orchestrator.py`) сам модель не использует: этапы, лимиты и состояние задаёт код. Агенты обмениваются только артефактами в `runs/<id>/`.

Все команды выполняются из папки проекта через `uv run ario ...`.

## 1. Подготовка (один раз)

```bash
uv sync
```

Создать `.env` по образцу `config/.env.example`. Для первого запуска нужны:

| Переменная | Что это |
|---|---|
| `RX_PATH` | Путь к репозиторию RX (рабочее дерево должно быть **чистым**, иначе тикет не будет взят) |
| `OPENROUTER_API_KEY` | Ключ OpenRouter |
| `ARIO_BUILD_COMMAND` | Штатная команда сборки RX (Directum Launcher: `do dirx build`) |
| `TFS_URL`, `TFS_PROJECT`, `TFS_PAT` | Доступ к TFS, если тикеты берутся оттуда (PAT с правом Work Items: Read) |

Остальные переменные (ветки, модели по ролям, запись на доску, графики) и их значения: [docs/guide/configuration.md](docs/guide/configuration.md). `.env` в репозиторий не попадает.

## 2. Запуск тикета

### Шаг 1. Положить тикет в `tickets/inbox/`

Из TFS по номеру:

```bash
uv run ario fetch --id 43702
```

Из TFS по запросу (Bug, тег `AI dev`, area `SmartInstruments\Antares`, не закрытые, до `TFS_MAX_ITEMS` новых):

```bash
uv run ario fetch
```

Показать, что будет взято, ничего не записывая:

```bash
uv run ario fetch --dry-run
```

Вручную: файл формата D01 `tickets/inbox/<id>.md` (пример: `evals/cases/90101.md`). Тикет, уже лежащий в любой папке состояний, повторно не скачивается и не перезаписывается.

### Шаг 2. Запустить поток

```bash
uv run ario run 43702
```

Порядок: analyst (локализует проблему и проверяет, хватает ли информации) → developer (правки и сборка) → reviewer. При `reject` ревьюера developer дорабатывает один раз, затем второе ревью. Прогон идёт от 1 до 10 минут.

Коды выхода:

| Код | Значение |
|---|---|
| 0 | Тикет готов (`done`) |
| 1 | Нужен человек (`needs-human`), причина в `tickets/needs-human/<id>.comments.md` |
| 2 | Ошибка настройки или TFS |
| 3 | Тикет не взят (например, RX не чистый) |

### Шаг 3. Посмотреть результат

Правка лежит в RX на ветке тикета, без коммита:

```bash
git -C <путь к RX> diff
```

Коммит и push выполняет человек.

Где что лежит:

| Что | Где |
|---|---|
| Тикет и комментарии агентов | `tickets/{inbox,in-progress,done,needs-human}/<id>.md` и `<id>.comments.md` |
| Результаты этапов | `runs/<id>/`: `analysis.md`, `development-N.md`, `review-N.md`, `state.json` |
| Полная трасса | `traces/<id>/events.jsonl` |

### Шаг 4. Разобрать, что делали агенты

Сводка по этапам (шаги, токены, доля кэша, вердикты):

```bash
uv run ario trace 43702
```

Пошаговая лента вызовов одного этапа (`analysis`, `development`, `review`):

```bash
uv run ario trace 43702 --steps --stage development
```

Ключ `--full` добавляет задачу, мысли модели и длинные тексты.

### Автоматический режим

Вместо отдельных `fetch` и `run` можно запустить наблюдателя: он раз в `ARIO_POLL_MINUTES` минут
(по умолчанию 5) забирает новые тикеты из TFS по запросу отбора и по одному, от самого старого,
ведёт их по потоку (очередь — папка `tickets/inbox/`).

```bash
uv run ario watch
```

- Остановка: Ctrl+C один раз: текущий тикет дорабатывает, новые не берутся; второй раз: сразу.
- `uv run ario watch --once` делает один цикл и выходит (подходит для планировщика задач).
- Тикет, который не взяли (например, в клоне RX чужие правки), ждёт следующего цикла; тикет в
  `needs-human` повторно сам не запускается, только вручную (`ario resume <id>`).
- Одновременно работает один наблюдатель; недоступный TFS обработку уже лежащих тикетов не
  останавливает. Тикеты, оставшиеся в `in-progress/` после сбоя или Ctrl+C, наблюдатель
  подхватывает сам, раньше новых.
- Тикет, который наблюдатель однажды взял, повторно не берётся, даже если файлы из папок убрали
  (журнал `watch-seen.json` в каталоге данных). Вернуть такой тикет в очередь:
  `uv run ario fetch --id N`.
- `uv run ario watch --dry-run` показывает, что взял бы опрос и что уже в очереди, ничего не
  запуская (безопасная проверка настроек).
- Наблюдатель и ручной `ario run` по другому тикету не должны работать в одном клоне RX
  одновременно: общей блокировки клона пока нет (будет вместе с параллельностью).
- После смены `.env`, `repos.yaml` или потока состояний наблюдатель нужно перезапустить.

### Вебхуки TFS (мгновенный запуск вместо ожидания опроса)

```bash
uv run ario watch --webhook
```

Наблюдатель дополнительно принимает вебхуки TFS (опрос остаётся запасным путём):
- событие work item (создан, изменён) запускает внеочередной цикл с обычным запросом отбора;
- голос «Waiting for author» или «Rejected» у PR нашего тикета запускает `rework --from-pr`; если
  новых замечаний нет, ничего не происходит (комментарии без голоса доработку не запускают).

Настройка: в `.env` задайте `ARIO_WEBHOOK_SECRET` (не короче 12 символов; без него вебхук не
запустится), при необходимости `ARIO_WEBHOOK_HOST` (по умолчанию только `127.0.0.1`) и
`ARIO_WEBHOOK_PORT` (8765). В TFS: Project settings → Service hooks → подписка Web Hooks на события
Work item created, Work item updated, Pull request updated; URL `http://<узел>:8765/ario/tfs`;
Basic authentication: любое имя и пароль из `ARIO_WEBHOOK_SECRET`. В подписке на work item
обязательно задайте фильтры (Area path и Tag, как в запросе отбора): без них опрос будет
запускаться на каждое изменение любого work item проекта. Приёмник должен быть
достижим с сервера TFS: вне localhost ставьте TLS-прокси (пароль Basic идёт открытым текстом).
Проверка вживую ещё не проводилась: после настройки подписки нажмите в TFS «Test».

### Доработка по замечаниям к PR

Если PR вернули с замечаниями, их можно передать агентам: тикет должен быть в `done/` (с открытым
PR). Developer правит ту же ветку, reviewer проверяет результат, новый коммит уходит в тот же
PR, в PR появляется ответ агента, на доске тикет возвращается в Development и снова в
ReadyForTesting.

```bash
uv run ario rework 60010 --from-pr
```

- `--from-pr` берёт активные ветки обсуждения PR (без закрытых, исправленных и ответов самого
  агента); уже учтённые замечания второй раз не берутся, пока в ветке нет нового комментария.
- `--note "текст"` (можно несколько раз) и `--file замечания.md` добавляют замечания вручную;
  ключи можно сочетать.
- На тикет не больше трёх доработок; замечания проверяются на prompt injection и сохраняются в
  `runs/<id>/rework-<N>.md`. Если ревью отклонит доработку, тикет уходит в `needs-human`.
- Чтобы тикет возвращался на доске в Development, добавьте в `config/ticket-flow.yaml` событие
  `rework_started` (образец в `config/ticket-flow.yaml.example`).

## 3. Если тикет упал

Продолжить с этапа, на котором остановились (после исправления причины: сеть, модель, дерево RX):

```bash
uv run ario resume 43702
```

Начать заново, откатить правки в RX: [docs/guide/restart.md](docs/guide/restart.md).
