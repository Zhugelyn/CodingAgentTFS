# ArioCodingAgent

Харнесс из трёх агентов (analyst → developer → reviewer) на OpenHands SDK. Берёт тикет, находит место проблемы в коде Directum RX, вносит правку, собирает решение и проверяет её. Результат остаётся в репозитории RX на отдельной ветке тикета **без коммита и push**: их делает человек.

Оркестратор (`src/ario/orchestrator.py`) сам модель не использует: этапы, лимиты и состояние задаёт код. Агенты обмениваются только артефактами в `runs/<id>/`.

Все команды выполняются из папки проекта через `uv run ario ...`.

## 1. Подготовка (один раз)

Установить зависимости:

```bash
uv sync
```

Создать `.env` по образцу `config/.env.example` и заполнить:

| Переменная | Что это |
|---|---|
| `RX_PATH` | Путь к репозиторию RX |
| `BASE_BRANCH` | Ветка, от которой создаётся ветка тикета (по умолчанию `master`) |
| `BRANCH_TEMPLATE` | Имя ветки тикета, обязателен `{id}`, например `antares/ai-{id}` |
| `ARIO_BUILD_COMMAND` | Штатная команда сборки RX (Directum Launcher: `do dirx build`) |
| `OPENROUTER_API_KEY` | Ключ OpenRouter |
| `LLM_MODEL` | Модель по умолчанию (формат LiteLLM, например `openrouter/qwen/qwen3.8-27b`) |
| `ANALYST_MODEL`, `DEVELOPER_MODEL`, `REVIEWER_MODEL` | Модель по ролям; пусто: берётся `LLM_MODEL` |
| `TFS_URL`, `TFS_PROJECT`, `TFS_PAT` | Доступ к TFS (PAT с правом Work Items: Read) |
| `TFS_WIQL`, `TFS_MAX_ITEMS` | Свой запрос отбора и лимит тикетов за один `fetch` (необязательно) |

`.env` в репозиторий не попадает. Секреты (`OPENROUTER_API_KEY`, `TFS_PAT`) нигде, кроме `.env`, не хранятся.

Перед запуском рабочее дерево RX должно быть **чистым**: иначе тикет не будет взят.

## 2. Запуск тикета

### Шаг 1. Положить тикет в `tickets/inbox/`

Из TFS по номеру:

```bash
uv run ario fetch --id 43702
```

Из TFS по запросу (Bug, тег `AI dev`, area `SmartInstruments\Antares`, не закрытые, до `TFS_MAX_ITEMS` новых):

```bash
uv run ario fetch
```

Показать, что будет взято, ничего не записывая:

```bash
uv run ario fetch --dry-run
```

Вручную: файл формата D01 `tickets/inbox/<id>.md` (пример: `evals/cases/90101.md`). Тикет, уже лежащий в любой папке состояний, повторно не скачивается и не перезаписывается.

### Шаг 2. Запустить поток

```bash
uv run ario run 43702
```

Порядок: analyst (локализует проблему и проверяет, хватает ли информации) → developer (правки и сборка) → reviewer. При `reject` ревьюера developer дорабатывает один раз, затем второе ревью. Прогон идёт от 1 до 10 минут.

Коды выхода:

| Код | Значение |
|---|---|
| 0 | Тикет готов (`done`) |
| 1 | Нужен человек (`needs-human`), причина в `tickets/needs-human/<id>.comments.md` |
| 2 | Ошибка настройки или TFS |
| 3 | Тикет не взят (например, RX не чистый) |

### Шаг 3. Посмотреть результат

Правка лежит в RX на ветке тикета, без коммита:

```bash
git -C <путь к RX> diff
```

Коммит и push выполняет человек.

Где что лежит:

| Что | Где |
|---|---|
| Тикет и комментарии агентов | `tickets/{inbox,in-progress,done,needs-human}/<id>.md` и `<id>.comments.md` |
| Результаты этапов | `runs/<id>/`: `analysis.md`, `development-N.md`, `review-N.md`, `state.json` |
| Полная трасса | `traces/<id>/events.jsonl` |

### Шаг 4. Разобрать, что делали агенты

Сводка по этапам (шаги, токены, доля кэша, вердикты):

```bash
uv run ario trace 43702
```

Пошаговая лента вызовов одного этапа (`analysis`, `development`, `review`):

```bash
uv run ario trace 43702 --steps --stage development
```

Ключ `--full` добавляет задачу, мысли модели и длинные тексты.

## 3. Метрики и токены

Токены берутся у провайдера (поле `usage` в каждом ответе модели) и пишутся в трассу `traces/<id>/events.jsonl`. Сами мы токены не считаем.

Сводка по тикету: по этапам время, шаги, токены запросов и ответов, максимум контекста, доля кэша провайдера, инструменты, повторы запросов к модели, вердикты:

```bash
uv run ario trace 43702
```

По шагам одного этапа: что вызвал агент, размер контекста на каждом шаге, сколько ждал модель:

```bash
uv run ario trace 43702 --steps --stage analysis
```

Те же шаги, но с задачей, мыслями модели и длинными текстами:

```bash
uv run ario trace 43702 --steps --stage development --full
```

Итоги запуска каждого агента (шаги, токены запросов и ответов, токены из кэша) прямо из трассы:

```bash
grep agent_finished traces/43702/events.jsonl
```

Метрики набора тикетов (время, шаги, токены, максимум контекста, повторы, ошибки инструментов) попадают в отчёт `evals/runs/<время>/report.md`, который создаёт `uv run ario eval`.

Как читать цифры:

| Показатель | Что означает |
|---|---|
| Токены запросов | Сумма всего, что отправлено модели на каждом шаге (история отправляется заново), примерно «шаги × средний контекст». Это не новые токены |
| Из кэша провайдера | Часть токенов запросов, прочитанная из кэша (дешевле и быстрее); входит в счётчик запросов |
| Цена | Реальная стоимость по данным OpenRouter, в долларах; учитывает скидку за кэш |
| Максимум контекста | Размер самого большого запроса; ограничен лимитом `max_context_tokens` (128k) |
| Шаги | Число вызовов инструментов; лимит в `guardrails.yaml` считает итерации модели, поэтому шагов может быть больше лимита |

Что учитывать:
- Цена прогона берётся из ответов OpenRouter (реальная, с учётом кэша провайдера), пишется в трассу (`cost_usd` на агенте, `cost_total` на каждом вызове), показывается в `ario trace` («цена» по этапам и итог за все попытки) и в отчёте evals. Работает для моделей `openrouter/...`; для других провайдеров цены нет. Сверить можно в OpenRouter → Activity.
- После `ario resume` этап суммируется по всем попыткам. Для одной попытки смотрите события `agent_finished` по времени.
- Если провайдер не вернул кэш в `usage`, доля кэша будет 0%: это «нет данных», а не обязательно «кэша нет».

### Графики и разбор в UI (OpenTelemetry + Phoenix)

Метрики и тайминги прогонов можно выгрузить в [Arize Phoenix](https://github.com/Arize-ai/phoenix): в UI видны трассы тикетов (тикет → прогон → этап → агент → вызовы модели и инструментов), токены, кэш, время, фильтры по атрибутам. **Текст не экспортируется** (промпты, мысли, аргументы и результаты инструментов, код, тикеты): только числа, имена инструментов и моделей, статусы и время.

Установить Phoenix один раз в отдельное окружение (зависимости проекта он не меняет, данные в `.phoenix/`, не коммитятся). Постоянное окружение надёжнее `uvx`: на Windows `uvx` может падать на блокировке файлов в кэше.

```bash
uv venv .phoenix/venv --python 3.13
```

```bash
uv pip install --python .phoenix/venv/Scripts/python.exe arize-phoenix
```

Запустить сервер (интерфейс на `http://localhost:6006`; на Linux путь `.phoenix/venv/bin/phoenix`):

```bash
PHOENIX_WORKING_DIR=.phoenix PHOENIX_TELEMETRY_ENABLED=false .phoenix/venv/Scripts/phoenix.exe serve
```

В PowerShell:

```powershell
$env:PHOENIX_WORKING_DIR=".phoenix"; $env:PHOENIX_TELEMETRY_ENABLED="false"; .phoenix/venv/Scripts/phoenix.exe serve
```

Выгрузить трассу тикета (любой прошлый тоже; повторная выгрузка дублей не создаёт):

```bash
uv run ario export-otel 43702 --endpoint http://localhost:6006/v1/traces
```

Посмотреть, что будет выгружено, ничего не отправляя:

```bash
uv run ario export-otel 43702 --dry-run
```

Автоматически в конце каждого `ario run` и `ario resume`: задайте в `.env`

```
ARIO_OTLP_ENDPOINT=http://localhost:6006/v1/traces
```

Сбой выгрузки прогон не ломает, печатается предупреждение.

**Важно:** не задавайте `OTEL_EXPORTER_OTLP_*` и `LMNR_*`. OpenHands SDK при их наличии сам отправляет **полные тексты запросов к модели** (код RX, тикеты), поэтому харнесс при такой настройке откажется стартовать. Осознанный обход: `ARIO_ALLOW_SDK_TELEMETRY=1`.

Что смотреть в Phoenix: вкладка Traces (по одной трассе на тикет, раскрывается до вызовов), колонки времени и токенов, фильтр по атрибутам (`ario.outcome`, `ario.stage`, `gen_ai.request.model`, `ario.usage.cache_hit_ratio`); спаны `llm call N` показывают токены и размер контекста на каждом шаге, `tool ...` — время каждого инструмента, события `budget_nudge` и `limit_wrap_up` отмечают вмешательства харнесса. Phoenix принимает трассы, но не OTLP-метрики: графики «по тикетам во времени» строятся по атрибутам спанов. Реальная цена (данные OpenRouter с учётом кэша) лежит в атрибутах спанов `ario.cost_usd` (на агенте и на каждом вызове модели `llm call N`) и в `ario trace`. Модель в спанах: `ario.model`. Встроенное поле «Total Cost» Phoenix для наших спанов не заполняется намеренно: он оценивал бы цену без скидки за кэш и завышал её в десятки раз. Трассы, выгруженные до появления цены, в Phoenix сохраняют старую оценку; чтобы убрать их, остановите Phoenix и удалите папку `.phoenix/`. Длительность корневого спана тикета включает паузы между запусками, активное время смотрите по спанам этапов.

#### Тексты запросов к модели (живая выгрузка, опционально)

Обычная выгрузка выше текст не содержит. Чтобы видеть **полные запросы и ответы модели** (системный промпт, историю, вызовы инструментов), включите живую выгрузку: каждый вызов модели превращается в спан в отдельном проекте Phoenix `ArioCodingAgent-LLM`, спаны каждого тикета собираются в сессию (вкладка Sessions, `session.id` = номер тикета; на спане метки этапа и роли).

Это **код RX и тексты тикетов**, поэтому функция выключена по умолчанию и работает только с локальным Phoenix. Секреты (ключи, токены) маскируются перед отправкой.

Один раз поставить необязательные пакеты:

```bash
uv sync --extra telemetry
```

В `.env`:

```
ARIO_OTLP_ENDPOINT=http://localhost:6006/v1/traces
ARIO_OTLP_LLM_CONTENT=1
```

Дальше `uv run ario run <id>` (и `resume`, `eval`) отправляет запросы к модели в Phoenix по ходу работы; в начале вывода будет строка «Живая выгрузка запросов к модели (с текстом) включена». Для не локального сервера харнесс откажется стартовать; осознанный обход: `ARIO_ALLOW_REMOTE_LLM_CONTENT=1`.

Особенности: это отдельная трасса от «обычной» (проекты `ArioCodingAgent` и `ArioCodingAgent-LLM`), в проекте с текстом Phoenix сам показывает оценочную цену (без скидки за кэш), точная цена остаётся в `ario trace`. Каждый запрос содержит всю историю, поэтому объём данных большой (единицы–десятки МБ на тикет); старые прогоны так не выгрузить, только новые.

## 4. Если тикет упал или нужен перезапуск

Продолжить с этапа, на котором остановились (после исправления причины: сеть, модель, дерево RX):

```bash
uv run ario resume 43702
```

Начать тикет заново (команды сброса нет): вернуть `tickets/<папка>/<id>.md` в `tickets/inbox/`, убрать `runs/<id>` и `traces/<id>` (удобно переносить в `runs/_archive/` и `traces/_archive/`), откатить правки в RX и снова запустить `ario run`.

Откатить правки в RX:

```bash
git -C <путь к RX> restore .
```

После этого переключиться на свою рабочую ветку и при желании удалить ветку тикета (`git -C <путь к RX> branch -D <ветка тикета>`).

## 5. Набор тикетов с ожиданиями (evals)

Прогнать все кейсы из `evals/cases/` по ожиданиям `evals/expected.yaml`:

```bash
uv run ario eval
```

Отдельные кейсы:

```bash
uv run ario eval --only 90102 90103
```

Отчёт с метриками (время, шаги, токены, повторы запросов) пишется в `evals/runs/<время>/report.md`. Кейсы с правками кода требуют чистого дерева RX; после такого кейса откатите RX.

```bash
uv run pytest
```

```bash
uv run ruff check src tests
```


## 7. Настройка поведения агентов

| Что менять | Где |
|---|---|
| Роли агентов | `agents/<роль>/AGENTS.md` и `agents/<роль>/tools.yaml` |
| Общие правила RX | `AGENTS.md` в корне |
| Навыки по RX | `skills/<имя>/SKILL.md` |
| Лимиты шагов, времени, контекста, запрещённые пути, правила injection | `config/guardrails.yaml` |

Не коммитить: `.env`, `runs/`, `traces/`, содержимое `tickets/*/`.
