# Спецификация MCP-сервера «RX tools»

Единственная часть переноса, где нужен код: LibreChat не умеет читать и править ваш репозиторий RX. Сервер запускается на машине с RX и подключается в `librechat.yaml` (см. `librechat.yaml.snippet`). Инструменты и защита берутся из харнесса: `src/ario/tools/*`, `src/ario/agents/readonly_tools.py`, `dev_tools.py`, `src/ario/guardrails/*`.

## Инструменты и кому они доступны

| Инструмент | Параметры | Что делает | analyst | developer | reviewer |
|---|---|---|---|---|---|
| `find_files` | `pattern`, `path?` | поиск файлов по имени в RX | да | да | да |
| `search_text` | `pattern`, `path?`, `glob?` | поиск по содержимому (регулярное выражение, с таймаутом) | да | да | да |
| `read_file` | `path`, `offset?`, `limit?` | чтение фрагмента файла с номерами строк | да | да | да |
| `edit_file` | `path`, `old_text`, `new_text` | замена ровно одного вхождения в существующем файле, сохраняет CRLF и BOM, новых файлов не создаёт | нет | да | нет |
| `git_prepare_branch` | `ticket_id`, `type?` | проверяет чистоту дерева RX и создаёт ветку тикета от `BASE_BRANCH` по `BRANCH_TEMPLATE` (по умолчанию `antares/ai-{id}`) | нет | да | нет |
| `git_status` | нет | состояние ветки | нет | да | да |
| `git_diff` | `path?` | изменения ветки относительно базовой, включая новые файлы | нет | да | да |
| `build` | `project?` | `do dirx build` (команда `ARIO_BUILD_COMMAND`), агенту возвращаются только ошибки, без предупреждений | нет | да | нет |

В LibreChat доступ к инструментам задаётся на уровне агента (какие инструменты MCP-сервера выбраны), поэтому у analyst и reviewer просто не отмечены `edit_file`, `git_prepare_branch`, `build`. Если конструктор позволяет выбирать по отдельности, этого достаточно; иначе делаем три отдельных сервера (`rx-read`, `rx-dev`, `rx-build`) и выдаём их агентам.

## Защита внутри сервера (не зависит от модели)

Обязательно, потому что в LibreChat нет нашего слоя guardrails. Берётся из `config/guardrails.yaml` и `src/ario/guardrails/boundaries.py`:
- все пути сначала отсекаются по подозрительным формам (UNC, альтернативные потоки `:`, имена устройств Windows), затем приводятся к абсолютным и проверяются на нахождение внутри RX;
- запрет записи: файлы сборки (`*.csproj`, `Directory.Build.*`, `nuget.config`, `.git`, `bin/`, `obj/`, `*.g.cs` и др., список в `write_deny`);
- запрет чтения: ключи, `.env`, сертификаты и др. (`read_deny`);
- `edit_file` не создаёт файлы и не правит вне RX; `git_prepare_branch` отказывает при грязном дереве; commit, push, reset, switch на чужие ветки не предоставляются совсем;
- вывод инструментов проходит маскирование секретов (`Masker`), размер вывода ограничен;
- сборка и поиск идут с таймаутом; окружение процесса сборки очищено от секретов (`clean_env`).

## Как собрать
Вынести эти модули в MCP-сервер на Python (официальный SDK `mcp`), тонкая обёртка над существующим кодом; тесты инструментов уже есть (`tests/test_tools_*`, `tests/test_security.py`). Транспорт: `streamable-http` на локальный порт машины с RX или `stdio`, если LibreChat запускается на этой же машине. Отдельная история в карте (S14), когда вы подтвердите этот путь.
