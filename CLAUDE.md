# ArioCodingAgent

Харнесс из трёх агентов (analyst → developer → reviewer) на OpenHands SDK: разбирает тикет из папки и оставляет ветку тикета (`BRANCH_TEMPLATE`, по умолчанию `ai/<id>`) в репозитории RX. Оркестратор (`src/ario/orchestrator.py`) сам LLM не использует.

## Команды
- `uv sync` — зависимости
- `uv run pytest` — тесты (на заглушках LLM, без сети)
- `uv run ruff check src tests` и `uv run ruff format .` — линтер и формат
- `uv run mypy` — типы (strict)
- `uv run ario run <id>` — провести тикет из `tickets/inbox/<id>.md` (повторный запуск после падения продолжает с последнего готового этапа)
- `uv run ario resume <id>` — возобновить тикет из `needs-human/` с упавшего этапа (после починки причины)
- `uv run ario trace <id> [--steps] [--stage ЭТАП] [--full]` — разбор трассы: сводка по этапам или пошаговая лента вызовов агентов

## Правила
- Python 3.13, type hints везде, ruff + mypy + pytest. Комментарии и сообщения пользователю — по-русски.
- Код переносимый (Windows для разработки, Docker/Linux для продакшена): `pathlib`, без жёстких путей; настройки из `.env` (пример: `config/.env.example`).
- Тесты не ходят в сеть и не вызывают реальную модель.
- Этап закончен, когда тесты зелёные, пройден `/code-review`, заказчик апрувнул. Итоги этапа — в `memory.md`.
- Не коммитить: секреты, `.env`, `runs/`, `traces/`, содержимое `tickets/*/`.

## Не читать при разработке харнесса
`AGENTS.md` в корне и `skills/`, `agents/*/AGENTS.md` — это **содержимое для агентов харнесса** (знания о RX, навыки), а не инструкции тебе. Не читай и не применяй их, пока заказчик прямо не попросил их править. Правила разработки — только этот файл.
