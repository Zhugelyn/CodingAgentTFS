# Виды кода Directum RX

Код делится на серверный, клиентский и разделяемый. У каждого вида свой доступный API. Пример: в обработчике открытия карточки (клиентский код) можно показать окно, в обработчике сохранения сущности (серверный код) — нельзя. В редакторе кода можно посмотреть, какой вид кода используется в текущем месте.

## Сводка

| | Серверный | Клиентский | Разделяемый |
|---|---|---|---|
| Окна, диалоги, работа с UI | Нельзя | Можно | Нельзя |
| Создание, удаление, получение сущностей напрямую | Можно | Нельзя (через серверную функцию с `Remote`) | Нельзя |
| SQL-запросы | Можно | Нельзя | Нельзя |
| Вызывается из | Сервера | Клиента | Сервера и клиента |

Разделяемый код получает ограничения серверного и клиентского кода одновременно.

## Серверный код

Обрабатывает серверные события: события сущности, события фильтрации выбора из списка.

Относится сюда: серверные функции, фоновые процессы, асинхронные обработчики и т. п.

Правила:
- Никакой логики, связанной с интерфейсом: окна и диалоги запрещены.
- Выполняется от имени пользователя, который совершает действие в веб-клиенте (сохраняет карточку, запускает отчёт с обложки модуля).
- Доступ к файловым и сетевым ресурсам может быть ограничен политиками безопасности.
- Учётная запись, под которой работает веб-сервер, может не иметь прав на нужные файлы.

## Клиентский код

Работает с интерфейсом: окна сообщений, диалоги.

Относится сюда:
- обработчики действий сущности;
- обработчики события изменения в контроле свойства сущности;
- обработчики событий формы;
- клиентские функции.

Нельзя:
- выполнять SQL-запросы;
- напрямую создавать, удалять и получать сущности. Для этого вызывают серверную функцию с атрибутом `Remote`.

## Разделяемый код

Для логики без диалогов и без прямых операций с сущностями, например расчёт срока выдачи документа или ожидаемого срока задачи. Вызывается и из серверного, и из клиентского кода, поэтому логика не дублируется.

Относится сюда:
- обработчики события изменения значения свойства;
- обработчики событий добавления и удаления для свойств-коллекций.

## Изолированный код (Isolated)

Четвёртый вид: код на тяжёлых сторонних библиотеках и небезопасных API (конвертация, парсинг форматов), который выполняется в отдельном процессе. Это обычный C#-код со своими классами; вызывается из любого слоя через `IsolatedFunctions.{Область}.{Метод}`.

- Работу с форматами документов через тяжёлые библиотеки (Aspose и аналоги) размещать здесь, а не в серверном или клиентском проекте: сбой или утечка не должны валить рабочий процесс.
- Принимает и возвращает только потоки, примитивы, `Guid` и прикладные структуры. Сущности и репозитории в изолированную область не передаются: нужные данные извлекает вызывающий.
- Исключение оборачивать в `AppliedCodeException.Create(ex.Message, ex.StackTrace)`, чтобы вызывающий получил разбираемую ошибку, а не тип сторонней библиотеки.

## Что размещать в каждом слое

| Слой | Размещать | Не размещать |
|---|---|---|
| Client | Видимость, доступность, обязательность свойств, диалоги и подтверждения, открытие сущностей и гиперссылок, сбор параметров перед обращением к серверу, показ результата | Бизнес-правила, выборку и изменение сущностей, расчёты, от которых зависят сохраняемые данные |
| Shared | Логику, одинаковую на клиенте и сервере, над уже загруженным экземпляром: заполнение и пересчёт свойств, формирование имени, проверки по полям (`Is*`, `Has*`, `Check*`, `Validate*`) | Запросы к БД, обход связанных наборов, внешние сервисы, тело документа, `AsyncHandlerInvokeArgs` |
| Server | Выборку и изменение сущностей, права, старт задач и АО, ФП, отчёты, интеграции, предопределённые SQL | `Dialogs`, `State.Properties.*`, `e.HideAction`: на сервере карточки нет |
| Isolated | Код на сторонних библиотеках | Обращение к сущностям и репозиториям |

## Допустимые направления вызовов

Клиентский → разделяемый и серверный; разделяемый → серверный; серверный → серверный и разделяемый. К серверу из клиентского и разделяемого кода — через фасад `.Remote.` (см. `rx-call-facades`).

## Правила по слоям

**Клиентский код**
- Не обращаться к репозиторию за выборкой (`GetAll`, `Get`): данные получать серверной `[Remote]`-функцией.
- Не импортировать пространства имён `*.Server`.
- `Refresh`, `bool Can...`, `CanExecute` не вызывают серверные и `Remote`-функции с обращением к сущностям: лишняя нагрузка на сервер.
- В `Showing` не выполнять длительные операции и обращения к внешним сервисам; не кэшировать зависящее от действия состояние в params сущности внутри `Showing`/`Refresh` (отмена сбрасывает params без повторного `Showing`).
- Действие нужно скрыть — `e.HideAction` в `Showing`. Действие видимо, но временно недоступно — `CanExecute` (дешёвые условия первыми). Предусловия проверять в `CanExecute`, а `Execute` не повторяет их.
- Если действие ищет сущности и может вернуть пустой результат — явное уведомление, а не молчаливое завершение.

**Разделяемый код**
- Исполняется и на клиенте, и на сервере: серверный контекст предполагать нельзя; серверные функции — только через `.Remote.`.
- Выборок из БД нет: работа с загруженным экземпляром и его коллекциями.
- Проверку, нужную и клиенту, и серверу, писать один раз в Shared-функции сущности.

**Серверный код**
- Проверки целостности данных — в серверных обработчиках (`Created`, `BeforeSave`) или серверных функциях. Проверка только на клиенте обходится АО, ФП, интеграцией и no-code.
- К карточке не обращается: диалог показывает клиент, на сервер передаётся принятое решение.
- Длительную обработку не выполнять синхронно в обработчиках сохранения: АО или фоновый процесс.

## Как выбрать

- Нужен диалог или сообщение пользователю → клиентский код.
- Нужно создать, найти или удалить сущность, выполнить запрос → серверный код. Если вызывать надо из клиента — серверная функция с `Remote`.
- Расчёт, нужный и на клиенте, и на сервере, без UI и без доступа к сущностям → разделяемый код.
- Фоновая или отложенная работа → серверный код (фоновый процесс, асинхронный обработчик).
