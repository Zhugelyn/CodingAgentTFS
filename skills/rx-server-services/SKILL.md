# Серверные сервисы Directum RX

Серверные компоненты ставятся на Linux и Windows. Порядок установки разный, **архитектура развёрнутой системы одинакова**.

## Как сервисы связаны

- Сервисы общаются друг с другом сообщениями через брокер RabbitMQ. Доставка гарантирована, даже если один из серверов недоступен.
- Веб-сервер масштабируется горизонтально: чем больше клиентов, тем больше машин с веб-сервером. Нагрузку между ними распределяют балансировкой.
- Балансировка трафика между серверами: Windows — IIS, Linux — обратный прокси HAProxy.
- Windows: службу `ServiceRunner` запускает и перезапускает сервисы, умеет несколько экземпляров одного сервиса на машине, следит за изменением конфигов и перезапускает сервисы при их изменении.
- Linux: Docker, каждый сервис — отдельный контейнер.

## Общий сервис (GenericService)

Объединяет четыре сервиса, которые обычно мало нагружены, чтобы экономить память и процессор:

1. `WorkflowBlockService` (WBS)
2. `Worker`
3. `ReportService`
4. `Widgets`

Эти четыре по умолчанию **отключены**: их работу выполняет общий сервис. Любой из них можно установить отдельно, когда нужно выделить ему больше ресурсов (например, под тяжёлые отчёты).

## Справочник сервисов

| Сервис | Что делает | Замечания |
|---|---|---|
| Веб-сервер | Доступ к данным и основная бизнес-логика. Аутентификация, контроль активности сессий. Обработка запросов клиента по HTTPS/HTTP (открыть карточку, назначить права). Ставит и снимает блокировки объектов. Принимает запросы среды разработки и `DeploymentToolCore` на публикацию решений | Блокировка снимается при закрытии объекта или если клиент долго не подтверждает сессию. Масштабируется количеством машин |
| NOMAD | Связь мобильных приложений с системой: документы, задачи, задания, поручения, файлы | — |
| Workflow (`WorkflowProcessService`, WPS) | Обработка схем задач: выбирает схему и блок, ставит блок в очередь, передаёт на исполнение в WBS, после завершения выбирает следующий | — |
| Выполнение блоков (`WorkflowBlockService`, WBS) | Запускает блок схемы из очереди, следит за выполнением, возвращает результат в WPS сообщением | По умолчанию отключён (его работу делает GenericService) |
| Предпросмотр (`PreviewService`) | Обслуживает запросы веб-сервера на предпросмотр версии документа в веб-клиенте, формирует содержимое | — |
| Хранение предпросмотра (`PreviewStorage`) | Хранит подготовленные данные предпросмотра, отдаёт клиенту, кэширует (неизменённый документ открывается быстрее). Описания предпросмотра лежат в БД | — |
| Асинхронные события (`Worker`) | Асинхронные вычисления: фоновые процессы по запросу планировщика, асинхронные обработчики. Для тяжёлых, долгих задач или задач со специальным окружением (ОС, ПО) | По умолчанию отключён (делает GenericService) |
| Планировщик (`JobScheduler`) | Вычисляет, когда запускать фоновые процессы по расписанию, и сообщением передаёт их `Worker` | Сам процессы не выполняет |
| Виджеты (`Widgets`) | Построение и работа виджетов. Настройки и данные виджетов — в БД | По умолчанию отключён (делает GenericService) |
| Индексирование (`IndexingService`) | Индексирует документы, задачи, задания, уведомления для поиска по критериям и полнотекстового | — |
| Отчёты (`ReportService`) | Генерация отчётов | По умолчанию отключён (делает GenericService) |
| Хранилища (`StorageService`) | Кладёт данные о документах и их содержимое в хранилище, отдаёт по запросу клиентов и сервисов. Путь хранения — в конфиге сервиса | Можно несколько экземпляров, каждый со своим файловым или объектным хранилищем |
| Клиентские подключения (`ClientsConnectionService`) | Создаёт подключения клиентов к серверу, по ним веб-сервер шлёт веб-клиенту сообщения о серверных событиях (новое задание, уведомление, замещение). Регулярно сообщает веб-серверу о подключённых клиентах, чтобы тот продлевал сессии | Два компонента: Centrifugo и ClientsConnectionService |
| Отложенные операции (`DelayedOperationsService`) | Принимает от сервисов сообщения об ошибочных операциях, откладывает до времени или до востребования, потом возвращает в исходную очередь; неактуальные удаляет | Пример: задание не выдало права, потому что документ заблокирован; когда документ освобождён, сообщение возвращается и задача продолжается |
| Интеграция (`IntegrationService`) | Обмен данными с внешними системами по OData: принимает HTTP-запросы, обрабатывает по заданной логике, возвращает ответ | — |
| Логирование (`LogService`) | Сохраняет лог-файлы веб-клиента и веб-агента в папку на сервере | — |
| Ключи (`KeyDerivation`) | Часть шифрования: создаёт и собирает материалы ключей, передаёт их `StorageService`. Хранит секреты сервиса и сертификаты шифрования | — |
| Изолированный код (`IsolatedArea`) | Выполняет прикладной код в изолированной области, отдельным процессом | Вызывать можно из веб-сервера, WBS, `Worker`, `ReportService`, `IntegrationService`, GenericService |
| Сообщения (`MessageBroker`) | Принимает сообщения от других сервисов и передаёт пользователям через провайдера сообщений | Не путать с RabbitMQ: это брокер между сервисами |

## Как использовать при разработке

- Прикладной код (обработчики, схемы, отчёты) исполняется в разных сервисах: серверные события карточки — веб-сервер; блоки задач — WBS; фоновые процессы и асинхронные обработчики — `Worker`; отчёты — `ReportService`; интеграция по OData — `IntegrationService`. Это важно при отладке: ошибку надо искать в логе того сервиса, где код реально выполнялся.
- Тяжёлые и долгие вычисления выносят в асинхронные обработчики или фоновые процессы, чтобы не нагружать веб-сервер.
- Блокировка объекта — штатное поведение платформы. Конфликт блокировок приводит к отложенной операции, а не к потере действия.
